# אשף הקמת עסקים — כלי מפתח פנימי

## מטרה וגבולות

אשף ההקמה מיועד למפתח בלבד, כדי לקצר ולהאחיד הקמת אפליקציות עסקיות חדשות. הוא אינו מסך ניהול של לקוח, אינו חלק מהאפליקציה המיוצאת ואסור לחשוף אותו למשתמשי קצה.

כל התקנה עסקית נשארת עצמאית: Repository פרטי ב־GitHub, פרויקט PostgreSQL ב־Neon, שירות Render, סודות ונתוני לקוחות נפרדים.

## הרצה ראשונה

מתוך סביבת הפיתוח של המאגר, ב־PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
py -m business_app.provisioning --output .\work\new-business-plan.json
```

האשף מבקש שם עסק, slug, קטגוריה ומודולים. קובץ התוכנית נוצר רק אם נתיב הפלט אינו קיים; אין דריסה שקטה של תוכנית קודמת.

## מה קיים בשלב זה

- תכנון התקנה נפרדת ל־GitHub, Neon ו־Render.
- בחירת קטגוריית עסק.
- בחירת המודולים הקיימים בלבד: קליטת פניות, ניהול פניות ומחשבון אומדן.
- שמות משאבים ייחודיים ומפתחות idempotency דטרמיניסטיים.
- ברירת מחדל לתוכנית Render מסוג Free ולאזור פרנקפורט.
- הצהרה מפורשת שאין אימות מחיר בזמן אמת ואין יצירת משאבים.
- מניעת הכללת סודות או נתוני לקוחות בתוכנית.

## מה עדיין לא מחובר

הפקת התוכנית היא שלב תכנון בלבד. יצירת Repository דרך GitHub, פרויקט Neon ושירות Render דורשת מתאמי API, הרשאות מתאימות, בדיקת זמינות/מכסות ותהליך התאוששות. אין לטעון שהקמה אוטומטית הושלמה לפני שהמתאמים נבנו ונבדקו מול חשבונות ספקים.

החיבורים הבאים ייבנו כשכבות נפרדות, עם אימות credentials מתוך משתני סביבה/מנגנון סודות, ללא כתיבת ערכי סוד לקובצי תוכנית או ללוגים. פעולות יקרות או בלתי הפיכות ידרשו אישור מפורש. פעולות יצירה חייבות להיות idempotent ולבדוק אם משאב קיים לפני ניסיון יצירה חוזר.

## יכולות ומגבלות מוצר

קטגוריית עסק אינה מפעילה יכולות שלא קיימות בקוד. מודולים כגון CRM מלא, מלאי, רכש, מסמכים, תורים, פרויקטים וכספים אינם חלק מה־Starter הנוכחי; בקשה למודול כזה תידחה עד שיפותח וייבדק בנפרד.

## אימות

```powershell
py -m pytest -q
```

הכלי אינו מיובא על ידי `app.py`, אינו מוסיף route לאפליקציה העסקית ואינו משנה את מסד הנתונים או את שירות Render הקיים.
