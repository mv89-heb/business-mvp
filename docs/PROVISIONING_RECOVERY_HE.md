# התאוששות בטוחה בתהליך Provisioning

## מטרה

למנוע יצירה כפולה כאשר בקשת יצירה ל־GitHub, Neon או Render התקבלה אצל הספק אך התשובה אבדה, או כאשר תהליך האשף נעצר בין יצירת המשאב לבין שמירת המזהה שלו.

## עקרונות

1. לפני POST ליצירת משאב נשמרת רשומת פעולה עם status=intent, ספק, שם משאב וסמן התאוששות אקראי בן 128 ביט.
2. סמן ההתאוששות נשמר במצב התהליך לפני כל פעולת כתיבה. הוא מזהה את ניסיון ההקמה, אינו סוד ואינו credential.
3. אם התהליך נעצר לאחר שמירת intent, ניסיון חוזר אינו שולח POST נוסף. הוא מבצע רק קריאות GET לאיתור משאב עם אותו סמן.
4. משאב מאומץ רק לאחר התאמת הסמן וגם אימות owner/organization/workspace, region, source, branch, plan ו־CI לפי הספק.
5. כאשר לא ניתן להוכיח בעלות — התהליך נעצר במצב unknown. אין מחיקה אוטומטית ואין ניסיון יצירה נוסף.

## מיקום הסמן אצל כל ספק

| ספק | מיקום הסמן | בדיקת התאוששות |
|---|---|---|
| GitHub | Repository description: Business application | Business Studio provisioning:<32 hex> | GET של Repository מדויק, private=true ו־description תואם |
| Neon | שם ענף ברירת־המחדל: main-bs-<12 hex> | GET של רשימת ענפי הפרויקט ואימות שהענף תואם ומסומן default |
| Render | משתנה סביבה לא־סודי BUSINESS_STUDIO_PROVISIONING_ID | GET של משתני הסביבה בשירות ואימות ערך מדויק, ואז אימות Free / Frankfurt / checksPass |

ה־Neon project שומר את שם הפרויקט העסקי; רק שם ענף ברירת־המחדל משתנה כדי לשאת סמן ייחודי. חיבור האפליקציה נלקח מברירת־המחדל של הפרויקט, ולא מסתמך על שם הענף.

## מצבי פעולה

- intent: הכוונה נשמרה לפני שליחת בקשת היצירה.
- unknown: תוצאת כתיבה אינה ידועה (timeout, תשובת 5xx או תשובת JSON פגומה).
- reconciling: ניסיון חוזר שמבצע קריאות GET בלבד.
- completed: מזהה המשאב נשמר ואומת.
- failed: התקבלה שגיאה ידועה שאינה מעידה על יצירה עמומה; לאחר תיקון ניתן לנסות שוב.

## מגבלות והתנהגות ידנית

ה־API-ים אינם מספקים טרנזקציה משותפת או מפתח idempotency אחיד לכל פעולות יצירת המשאבים. לכן המימוש אינו טוען ל־exactly-once. הוא משתמש בסמנים ספקיים ובמדיניות at-most-once:

- אם הסמן נמצא והמשאב תואם — האשף משחזר את המזהה וממשיך.
- אם הסמן אינו נמצא, אינו קריא או עדיין אינו גלוי — האשף עוצר ואינו שולח POST נוסף.
- אם קיים משאב באותו שם ללא סמן תואם — הוא אינו מאומץ לפי שם בלבד.
- אם נדרש טיפול ידני, המפתח בודק את תיאור ה־Repository, ענף ברירת־המחדל ב־Neon או משתנה הסביבה ב־Render. אין למחוק או לשנות משאב לפני אימות בעלות ונתונים. לאחר הבדיקה נדרשת פעולת התאוששות מפורשת; אין מסלול אוטומטי שמסמן משאב לא ידוע כ"לא נוצר".

## פרטיות וסודות

סמן ההתאוששות אינו מכיל סוד. מצב התהליך שומר מזהי משאבים, סטטוסי פעולה וסמן בלבד. מפתחות API, DATABASE_URL, סיסמת מנהל, SECRET_KEY וערכי סודות אחרים אינם נשמרים במצב או ביומן. משתנה Render BUSINESS_STUDIO_PROVISIONING_ID הוא מזהה correlation לא־סודי בלבד.

## בדיקות

בדיקות המימוש משתמשות ב־mocks ומכסות:
- timeout אחרי יצירת Repository, פרויקט Neon או שירות Render, ולאחריו התאוששות באמצעות סמן תואם;
- סמן חסר או משאב לא גלוי — ללא POST חוזר;
- מניעת אימוץ של משאב לא מזוהה;
- סיווג HTTP 5xx ותשובת JSON פגומה כמצב כתיבה עמום;
- סירוב להתאושש משירות Render שאינו Free, Frankfurt ו־CI-gated.

הבדיקות אינן יוצרות משאבי ענן אמיתיים ואינן מאמתות חיוב או זכאות Free אצל ספק.
