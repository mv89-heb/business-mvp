# אינטגרציות ספקים והקמה אוטומטית

## עקרון תכנון

האשף הוא כלי מפתח מקומי בלבד. מתאמי הספקים נמצאים בתיקיית business_app/provisioning/providers ומשתמשים ב-REST APIs רשמיים. כל לקוח מקבל Repository, פרויקט Neon ושירות Render נפרדים. חיפוש Neon תחום תמיד ל־NEON_ORG_ID המאושר.

Canva מנוהלת דרך חיבור Canva המאומת ב-ChatGPT (Canva MCP) עבור יצירת נכסי מותג ועיצובים. אין לשמור סיסמת Canva או טוקן Canva בקובצי התוכנית. חיבור Canva דרך אפליקציה עצמאית ידרוש OAuth, scopes ואישור של בעל החשבון; אין להניח שכל API כלול בכל תוכנית Canva.

## משתני סביבה לספקים

יש להגדיר רק במחשב המפתח / במנגנון סודות, לעולם לא ב-Git:

- GITHUB_TOKEN — GitHub fine-grained token עם הרשאות יצירת Repository פרטי.
- NEON_API_KEY — Neon API key.
- NEON_ORG_ID — חובה; תוחם את איתור ויצירת פרויקטי Neon לארגון המאושר ומונע חיפוש גלובלי בין ארגונים.
- RENDER_API_KEY — Render API key.
- RENDER_WORKSPACE_ID — מזהה סביבת העבודה שאושרה במפורש.

המתאמים אינם קוראים סודות מקובצי JSON ואינם מחזירים אותם בסטטוס החיבור.

## יכולות המתאמים

- GitHub: בדיקת זהות, איתור/יצירת Repository פרטי, פרסום Starter נקי דרך Git Data API, והשוואת עץ הקבצים למניעת פרסום כפול.
- Neon: בדיקת חיבור, איתור פרויקט קיים לפי שם בתוך NEON_ORG_ID בלבד, יצירת פרויקט בתוך הארגון המאושר עם compute מינימלי והחזרת URI לחיבור. פרויקט קיים יאומץ רק אם מזההו תואם לרשומת ההקמה המקומית. ה-URI הוא סוד; אין לכתוב אותו ללוגים או לקובצי מצב.
- Render: בדיקת סביבת עבודה, איתור שירות קיים ויצירת Web Service בתוכנית Free בלבד, בפרנקפורט, עם deploy רק לאחר מעבר בדיקות CI (checksPass).

## בטיחות ותפעול

1. לפני יצירה יש לבצע preflight לכל הספקים, לאמת הרשאות ולבדוק כפילויות. משאב קיים לא יאומץ לפי שם בלבד: שימוש חוזר מותר רק כאשר מזהה המשאב תואם לרשומת מצב מקומית של אותה תוכנית הקמה.
2. במקרה של timeout לאחר בקשת יצירה, אין לבצע retry אוטומטי. יש לבדוק קודם אם המשאב נוצר; אם אין מזהה משאב שמור התהליך ייעצר ולא יאמץ משאב קיים על סמך שם בלבד.
3. אין לאפשר בחירה של תוכנית Render בתשלום.
4. Neon Free eligibility ומחירים/מכסות משתנים לפי החשבון והתנאים. יצירת פרויקט מחייבת להעביר free_tier_verified=True רק לאחר בדיקה חיה ואישור שהעלות הצפויה אפס. ברירת המחדל היא חסימה; אם לא ניתן לאמת עלות אפס — עוצרים.
5. אין ליצור או לשנות משאבי ענן כחלק מבדיקות אוטומטיות. הבדיקות משתמשות ב-mocks בלבד.
6. יצירת שירות Render דורשת ש-GitHub repository כבר מחובר לחשבון Git Provider ב-Render. אם לא, יש לבצע חיבור ידני בלוח הבקרה לפני יצירת השירות.
7. מתאם GitHub יוצר Repository פרטי ומפרסם אליו את ה־Starter הנקי באמצעות Git Data API. ה־workflow ממשיך ליצירת Neon ו־Render, וממתין לאימות `/health` לפני סימון הצלחה.

## בדיקת חיבור מתוך Python

    from business_app.provisioning.providers import GitHubProvider, NeonProvider, RenderProvider

    # בדיקות חיבור בלבד — ללא יצירת משאבים
    print(GitHubProvider().check_connection())
    print(NeonProvider().check_connection())  # requires NEON_ORG_ID
    print(RenderProvider().check_connection())

## שכבת Orchestration

הקובץ `business_app/provisioning/workflow.py` מחבר את המתאמים לזרימת הקמה אחת:
- Preflight לפני כל יצירת משאב.
- ייצוא Starter נקי ופרסום GitHub דרך Git Data API.
- יצירה/איתור של Neon והעברת connection URI ל־Render בזיכרון בלבד.
- יצירה/איתור של Render Free בפרנקפורט, העברת `ADMIN_PASSWORD_HASH` במקום סיסמה גלויה והמתנה ל־`/health`.
- מצב workflow מקומי אטומי, ללא סודות, ועדכון התקדמות בכל שלב.
- עצירה בטוחה בכשל; אין מחיקה אוטומטית של משאבים שנוצרו.

להפעלה, שמירת תוכנית Dry Run תחילה ואז הרצת `py -m business_app.provisioning.execute --plan <path>`. ההפעלה דורשת הקלדה מפורשת של `CREATE`, אישור `ZERO-COST` והזנת סיסמת מנהל ללקוח. כל הבדיקות משתמשות ב־mocks בלבד.

ה־workflow אינו מבצע OAuth עצמאי ל־Canva. יצירת נכסי עיצוב נעשית דרך חיבור Canva המאומת ב־ChatGPT; שילוב עצמאי באשף דורש הרשאת API/OAuth נפרדת.


## מערכת לידים — אינטגרציות יעד

### זרימת הנתונים

`Website / WhatsApp Cloud API → Flask ingress → Neon PostgreSQL → integration outbox → Make או n8n → Gemini → callback מאומת → CRM`

Neon הוא מקור האמת היחיד ללידים, הודעות, סטטוסים, היסטוריית טיפול ותוצאות AI. Make/n8n אינם מאגר CRM חלופי; הם שכבת תזמור בלבד. כל אירוע מקבל מזהה idempotency כדי למנוע כפילויות בשליחה חוזרת.

### WhatsApp Cloud API

- קליטה דרך Webhook HTTPS רשמי של Meta.
- אימות GET באמצעות Verify Token ואימות POST באמצעות `X-Hub-Signature-256` מול App Secret.
- שמירת הודעה נכנסת וקישור לליד לפי מספר טלפון מנורמל.
- אין לשלוח הודעות יוצאות אוטומטיות כברירת מחדל. שליחה מחייבת הרשאה, חלון שירות/תבנית מתאימה ואימות עלויות Meta.
- אין להסתמך על קישור `wa.me` כתחליף ל־Cloud API: הוא פותח שיחה ידנית ואינו מזרים את תוכן השיחה למסד הנתונים.

### Gemini

- עיבוד דרך API עם מפתח שמוגדר כ־Secret בלבד.
- שימוש ב־Gemini לסיווג תחום, כוונת פנייה, דחיפות, תקציר והצעת שאלת המשך.
- אין להעביר ל־Gemini שם, טלפון, דוא״ל, כתובת או מזהים אישיים כברירת מחדל. יש לבצע צמצום/השחרת מידע לפני עיבוד.
- תוצאות AI הן המלצה בלבד; הן אינן משנות מחיר, סטטוס "נסגר" או שולחות הודעה ללקוח ללא מדיניות ואישור.

### Make או n8n

- ברירת מחדל מומלצת: n8n Community Edition בהתקנה עצמית, כאשר המפתח בלבד בונה ומנהל את ה־workflows והלקוחות אינם מקבלים גישה לעורך או אפשרות לשנות לוגיקה.
- Make Free מתאים לניסוי בנפח נמוך בלבד; מכסת הפעולות ותדירות ההרצה מגבילות שימוש תפעולי רציף.
- אין לפרוס n8n על Render Free ללא אחסון מתמיד וגיבויים. אין לשמור workflow state או credentials על filesystem זמני.
- כל חיבור ל־Webhook חייב להשתמש ב־HTTPS, סוד/חתימה, timeout, idempotency, retries מבוקרים ו־dead-letter/תור שגיאות.

### Canva

- יצירת Brand Kit, תבניות עיצוב ונכסי מותג מתבצעת דרך Canva.
- חיבור Canva מתוך ChatGPT אינו מעניק אוטומטית token לאשף המקומי. חיבור עצמאי מחייב Canva Developer App, OAuth ו־scopes מאושרים.
- אין לשמור סיסמת Canva או access token בקובצי Git, בתוכנית Dry Run או בלוגים.

### GPT — שכבת התזמור

GPT משמש כמנהל התהליך: איסוף דרישות, הכנת תוכנית, בדיקת Preflight, בחירת תבניות, הפעלת ספקים מאושרים, בדיקת CI/Health והפקת סיכום. פעולות כתיבה, יצירת משאבים, פריסה, שליחה ללקוח או פעולה בתשלום מחייבות אישור מפורש. אין להטמיע מפתח API של GPT או להניח שמנוי ChatGPT כולל שימוש API.

### מצב המימוש

נכון לגרסה זו:
- קיימים טופס אתר, שמירת לידים ב־Neon, מסך ניהול בסיסי, חיפוש, סטטוסים וייצוא CSV.
- קיים Webhook אופציונלי ל־Google Sheets.
- WhatsApp Cloud API, תור אירועים אמין, Gemini, Make/n8n ו־Canva OAuth עדיין דורשים מימוש וחיבור חשבונות.
- אין להציג את האינטגרציות העתידיות כפעילות לפני בדיקת חיבור ו־end-to-end.
